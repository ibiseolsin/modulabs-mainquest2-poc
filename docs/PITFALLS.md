# 삽질 기록

숫자가 나온다고 그 숫자가 맞는 건 아니더라고요. 만들면서 실제로 걸렸던 것들을 순서대로 적어둡니다.

앞의 두 개는 **모델이 아니라 정답 쪽이 틀린** 경우였고, 둘 다 집계 숫자로는 전혀 안 보였습니다.

---

## 1. 정답이 얼굴이 아니었다

데이터 12장에 얼굴 60개, `ground_truth.json`도 정상적으로 떨어졌습니다. 장당 5개씩 딱 맞고요. 숫자만 보면 아무 문제 없었어요.

그런데 이미지를 열어 보니 이렇게 생겼더군요.

![정답이 얼굴이 아니었던 상태](assets/pitfall_bad_faces.jpg)

붙여넣은 다섯 개 중 넷이 얼굴이 아니라 색색의 노이즈 덩어리입니다. 초록 상자는 전부 "여기 얼굴 있음"이라고 적어놓은 정답이고요.

**원인은 생성 해상도였습니다.** 얼굴을 256px로 바로 뽑았는데, Stable Diffusion 1.5는 512×512로 학습된 모델이라 그보다 작게 뽑으면 구조가 무너집니다. 512로 만들어서 나중에 줄이면 멀쩡해요.

이걸 못 봤으면 어땠을까요. 탐지기 셋을 돌려서 "재현율 12%" 같은 걸 받아들고, 아마 모델이 별로라고 결론 냈을 겁니다. **틀린 건 모델이 아니라 채점표였는데 말이죠.** 채점표가 틀리면 그 표로는 아무것도 판단할 수 없습니다.

그래서 `build_dataset.py`가 얼굴 풀을 `data/face_pool/`이랑 `face_pool_contact.png`로 따로 저장하게 고쳤습니다. **붙이기 전에 사람 눈으로 한 번 보게 만드는 것** 말고는 이런 걸 잡을 방법이 없더라고요.

---

## 2. 정답 상자가 얼굴보다 컸다

고치고 다시 돌렸더니 이번엔 이렇게 나왔습니다.

```
Haar   41.7%
YuNet  50.0%     ← 목표는 95%
YOLO   31.7%
```

셋 다 한참 미달입니다. 숫자만 보면 "이 방향은 안 되겠는데" 소리가 나오죠.

그런데 시각화를 열어보니...

![정답 상자가 얼굴보다 컸던 상태](assets/pitfall_gt_toobig.jpg)

빨간 상자마다 MISS라고 붙어 있는데, **그 안에 파란 예측 상자가 얼굴에 정확히 붙어 있습니다.** 신뢰도도 0.92, 0.50으로 멀쩡하고요. YuNet은 얼굴을 다 찾았는데 놓쳤다고 세어지고 있었던 겁니다.

**원인은 정답 상자를 "붙여넣은 정사각형 전체"로 잡은 것이었습니다.** 그 정사각형엔 얼굴만 있는 게 아니라 머리카락이랑 인물 사진의 배경까지 들어 있거든요. 탐지기는 얼굴만 잡으니까, 정답 넓이 대비 덮인 비율이 0.4 근처에서 맴돌면서 기준선(0.5)을 못 넘었습니다.

여기서 **`cover_thr`을 0.35로 낮추면 숫자가 바로 좋아집니다.** 실제로 잠깐 그럴까 싶었고요. 근데 그건 결과를 보고 나서 채점 기준을 결과 쪽으로 끌어당기는 거라, 그렇게 만든 표로는 뭘 판단할 수가 없습니다.

대신 정답을 고쳤습니다. 얼굴 풀 8장을 격자와 함께 띄워놓고 **얼굴이 실제로 차지하는 영역을 눈으로 읽어서 손으로 적었어요** (`build_dataset.py`의 `FACE_BOXES`). 합성할 때 그 비율을 붙이는 크기에 곱하면 정답 상자가 나옵니다.

정답은 모델이 정하는 게 아니라 사람이 정하는 거고, **모델 돌리기 전에** 정해야 합니다.

> **여기서 배운 것.** 기준 미달이 나왔을 때 첫 질문은 "모델이 나쁜가"가 아니라 **"채점표가 맞나"** 여야 합니다. 이 확인을 건너뛰면 멀쩡한 후보를 떨어뜨려요. 그리고 이걸 잡아낸 건 집계 숫자가 아니라 **상자를 그려놓은 이미지**였습니다. `build_dataset.py`가 이제 `data/gt_vis/`에 정답 오버레이를 같이 저장하는 이유입니다.

고치고 나니 50% → **96.7%** 가 됐습니다.

## 3. torchvision이 torch랑 안 맞았다

```
RuntimeError: operator torchvision::nms does not exist
```

그리고 그 여파로 `Could not import module 'CLIPImageProcessor'`까지.

CUDA 빌드를 이렇게 깔았던 게 문제였습니다.

```bash
pip install --upgrade torch --index-url https://download.pytorch.org/whl/cu128
```

cu128 인덱스의 최신이 `2.11.0+cu128`인데, 이미 깔려 있던 CPU 빌드가 `2.13.0`이었어요. pip 입장에선 **"이미 더 높은 버전이 있네"** 하고 그냥 넘어간 겁니다. 결과적으로 torch는 CPU 2.13, torchvision은 cu128 0.26인 짝 안 맞는 상태가 됐고요.

버전을 박아서 짝으로 강제 재설치하니 해결됐습니다.

```bash
pip install --force-reinstall --no-deps \
  --index-url https://download.pytorch.org/whl/cu128 \
  "torch==2.11.0+cu128" "torchvision==0.26.0+cu128"
```

`--upgrade`는 "이 인덱스 걸로 바꿔라"가 아니라 **"더 높은 버전이면 올려라"** 라는 뜻이었습니다. 다른 인덱스의 빌드로 갈아탈 땐 버전을 명시해야 하네요.

## 4. 환경 때문에 걸린 잔가지 둘

**OpenCV 5.0엔 Haar cascade XML이 없습니다.** 기준선을 돌리려는데 `cv2.data.haarcascades` 폴더가 텅 비어 있었어요. 5.x에서 빠진 모양입니다. `opencv-python<5`로 내리면 다시 들어옵니다.

**Windows 한글 경로에서 `cv2.FileStorage`가 파일을 못 엽니다.** 경로가 `C:\Users\김지훈\...`인데, 파일은 분명 있는데 로드하면 빈 분류기가 나옵니다. 에러도 안 나고요. XML을 파이썬으로 직접 읽어서 메모리로 넘기면 됩니다.

```python
fs = cv2.FileStorage(path.read_text(encoding="utf-8"),
                     cv2.FILE_STORAGE_READ | cv2.FILE_STORAGE_MEMORY)
c = cv2.CascadeClassifier()
c.read(fs.getFirstTopLevelNode())
```

참고로 `cv2.imread`는 같은 경로에서 멀쩡히 동작합니다. `FileStorage`만 그래요.

## 5. IoU로 채점했으면 후보 하나가 억울하게 졌다

이건 실수한 건 아니고 설계할 때 걸러낸 건데, 적어둘 만해서요.

탐지 채점의 표준은 IoU(교집합/합집합)입니다. 그런데 후보 중 `yolo_person`은 **얼굴이 아니라 사람 전체**를 잡아요. 정답이 얼굴 상자니까 IoU는 0.1 근처로 깔립니다.

IoU로 줄 세우면 얘가 꼴찌로 나오는데, **이 업무가 묻는 건 "상자가 정확한가"가 아니라 "그 얼굴이 가려지는가"** 잖아요. 사람 전체를 가려도 얼굴은 가려집니다.

그래서 채점 기준을 정답 얼굴 넓이 중 예측에 덮인 비율(coverage)로 바꿨습니다.

```
IoU       = 교집합 / 합집합     → 상자가 얼마나 정확한가
coverage  = 교집합 / 정답넓이   → 그 얼굴이 가려지는가    ← 이 업무는 이쪽
```

물론 사람 전체를 가리면 **가리는 넓이가 커져서 사진을 못 쓰게 되는** 손해가 생기는데, 그건 coverage로는 안 잡힙니다. 그래서 `장당 오탐`이랑 SAM 단계의 `마스크 화소 비율`로 따로 봤어요.

표준 지표를 그냥 가져다 쓰면 업무랑 다른 걸 재게 되더라고요. 채점 기준도 업무에서 가져와야 합니다.

## 6. 정확도로 기준을 잡았으면 도입할 값이 없다고 나왔다

이 업무는 실수의 무게가 한쪽으로 쏠려 있습니다.

- 얼굴을 **놓치면** → 그대로 공개 → 되돌릴 수 없음
- 엉뚱한 걸 **잡으면** → 담당자가 클릭 한 번으로 제외

정확도(precision과 recall의 균형)로 기준을 잡으면 오탐 줄이는 쪽으로 임계값이 조여지고, 그러다 작은 얼굴을 놓칩니다. 이 업무에선 그게 제일 안 좋은 결과인데 말이죠.

그래서 성공 기준을 **재현율 우선**으로 쓰고, 오탐은 "장당 2개 이하"라는 느슨한 상한만 걸었습니다. 자세한 건 [PROBLEM.md](PROBLEM.md)의 성공 기준 절에 있어요.

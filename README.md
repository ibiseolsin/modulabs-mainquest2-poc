# modulabs-mainquest2-poc

모두의연구소 AI 에이전트 1기 · Main Quest 2

## 행사 사진에서 가려야 할 얼굴을 자동으로 찾아 주는 도구

단체 사진을 블로그나 모집 페이지에 올리려면 동의 안 받은 사람 얼굴을 가려야 합니다. 그런데 행사 한 번에 사진이 몇백 장씩 나오다 보니, 담당자가 하나하나 열어서 눈으로 찾고 블러 씌우는 작업이 하루를 잡아먹죠. 게다가 뒤로 갈수록 지쳐서 뒷줄의 작은 얼굴을 놓치기 시작합니다. **한 장만 놓쳐도 유출이고, 올라간 다음엔 주워 담을 수가 없고요.**

그래서 **"찾는 일"만 떼어내 자동화**해 봤습니다. 가릴지 말지, 올릴지 말지는 여전히 사람이 정합니다.

![파이프라인](poc/assets/figure_pipeline.jpg)

| 후보 | 재현율 | 놓침 | 오탐(장당) | 장당 시간 |
| --- | --- | --- | --- | --- |
| 기준선 · Haar Cascade | 75.0% (45/60) | 15 | 0.25 | 0.086초 |
| **YuNet** ← 선정 | **96.7% (58/60)** | **2** | **0.00** | **0.044초** |
| YOLOv8n (person) | 41.7% (25/60) | 35 | 0.17 | 0.522초 |
| ~~외부 Vision API~~ | — | — | — | 개인정보 조건 때문에 **점수도 안 재고 탈락** |

여기에 SAM을 붙여 네모난 블러를 사람 모양으로 다듬었더니 **가리는 넓이가 29.3% 줄었습니다.**
모델 셋이 한 줄로 이어집니다 — **Stable Diffusion**(테스트 데이터 생성) → **YuNet**(탐지) → **MobileSAM**(마스크 정제).

## 먼저 밝혀 둘 것 ⚠️

**이 업무 상황은 제가 지어낸 겁니다.**

저는 지금 맡고 있는 실무가 없는 캠프 수강생이라, 실제 담당 업무 대신 **운영팀의 콘텐츠 제작 업무를 가상으로 설정**하고 진행했습니다. 위에 적은 "몇백 장", "하루가 걸린다" 같은 것들도 실제로 물어보거나 재 본 값이 아니라 그럴듯하게 잡은 숫자예요.

| | |
| --- | --- |
| 🔸 **지어낸 것** | 업무 절차, 발생량(200~500장), 처리 시간(장당 1~3분), 현행 누락률(5%) |
| 🔹 **실제로 잰 것** | 후보 셋의 탐지 성능, SAM 마스크 축소율, 합성 데이터 60개 얼굴과 그 정답 |

그래서 이 저장소가 보여줄 수 있는 건 **"기술적으로 되긴 되네"까지**입니다. 원래 사람이 얼마나 걸렸는지를 모르니 "얼마나 좋아졌다"는 말은 할 수가 없어요. 성공 기준 세 개를 다 넘겼지만 **그 기준선 자체가 제가 정한 가정값**이라, 통과했다고 도입할 만하다는 뜻은 아닙니다. (사람이 사실 2%만 놓치고 있었다면 기준은 98%여야 하고, 그럼 96.7%는 오히려 미달이죠.)

어디까지가 가정이고 어디부터가 측정인지는 [PROBLEM.md 0-3절](docs/PROBLEM.md#0-3-무엇이-가정이고-무엇이-실제인가)에 표로 갈라놨습니다.

## 왜 이렇게 만들었나

**최종 판정을 모델한테 안 넘겼습니다.** 사진이 한 번 공개되면 되돌릴 수가 없어서요. 모델은 "여기 가려야 할 것 같은데요" 하고 후보만 띄우고, 확인 버튼은 사람이 누릅니다.

이 구조 덕분에 실수의 무게가 한쪽으로 쏠립니다.

- **놓치면** → 그대로 공개 → 되돌릴 수 없음 💀
- **잘못 잡으면** → 담당자가 클릭 한 번으로 제외 🤷

그래서 정확도가 아니라 **재현율(안 놓치는 비율)** 을 기준으로 잡았습니다. 정확도로 줄을 세우면 오탐을 줄이는 쪽으로 튜닝하게 되고, 그러다 작은 얼굴을 놓쳐요. 이 업무에선 그게 제일 나쁜 결과고요.

**후보는 크기가 아니라 성격으로 벌렸습니다.** 같은 모델의 대·중·소를 늘어놓으면 "큰 게 느리고 정확하다"는, 재 보기 전에도 아는 얘기만 나옵니다. 그래서 고전 방식 / 얼굴 전용 / 범용 탐지로 갈랐고, **지금 쓸 수 있는 방식(Haar)을 기준선으로 반드시 넣었습니다.**

외부 Vision API는 성능을 아예 안 쟀습니다. 입력이 **가리기 전 원본 사진**이잖아요. 개인정보 가리려고 만드는 도구가 원본을 밖으로 보내면 앞뒤가 안 맞습니다. 점수를 매겨두면 "근데 얘가 제일 잘하는데..." 하는 미련이 남아서, 아예 재지 않았습니다.

## 돌려보기

```bash
pip install -r requirements.txt
```

GPU 없으면 `requirements.txt`의 torch 세 줄을 지우고 `pip install torch torchvision` 하시면 됩니다. 탐지는 CPU로도 충분히 빠르고, 데이터 생성만 느려져요(장당 1분쯤).

YuNet 가중치(228KB)는 저장소에 들어 있어서 따로 받을 게 없습니다. YOLO·SAM이랑 Stable Diffusion 가중치(4.5GB)는 처음 돌릴 때 알아서 받아옵니다.

> 💡 **1단계는 건너뛰어도 됩니다.** `poc/data/`에 생성된 사진과 정답이 이미 들어 있어서, **GPU 없이 2단계부터 바로** 돌려볼 수 있어요.

### 1. 테스트 데이터 만들기

```bash
cd poc && python build_dataset.py --n-scenes 12 --out data
```

빈 강의실 12장이랑 얼굴 8명을 SD로 만들어서 합성합니다. 정답 상자도 여기서 확정되고요.

만들고 나면 **이 둘은 꼭 눈으로 확인하세요.** 제가 이걸 건너뛰어서 두 번 헛돌았습니다 ([PITFALLS.md](docs/PITFALLS.md)).

- `data/face_pool_contact.png` — 생성된 게 진짜 얼굴 맞나?
- `data/gt_vis/` — 정답 상자가 얼굴에 제대로 붙었나?

### 2. 후보 셋 비교

```bash
python detect_faces.py --candidates baseline_haar,yunet_face,yolo_person
```

`results/<후보>/vis/`에 채점 결과가 그려져 나옵니다. 🟩 초록은 잡은 정답, 🟥 빨강은 놓친 정답(MISS), 🟦 파랑은 예측 상자랑 신뢰도예요.

임계값 바꿔가며 여러 번 돌려도 **이전 결과를 안 덮어씁니다** (`__2`, `__3`이 붙어요).

```bash
python detect_faces.py --candidates yunet_face --yunet-conf 0.5 --cover-thr 0.6
```

### 3. SAM으로 마스크 다듬기

```bash
python refine_sam.py --detector yunet_face
```

`results/sam_refined/`에 `*_box.jpg`(네모 블러)랑 `*_sam.jpg`(마스크 블러)가 나란히 저장됩니다.

### 4. 시연 이미지

```bash
python make_figures.py --scene scene_03.png
python make_pitfall_figures.py     # 삽질 재현 → docs/assets/
```

## 결과 보기

### 같은 사진, 세 후보

![후보 비교](poc/assets/figure_compare.jpg)

Haar는 작은 얼굴이랑 정면 아닌 얼굴에서 무너집니다. 예상대로였고요.

YOLO의 41.7%는 좀 다른 얘기입니다. **합성 이미지라 얼굴만 있고 몸통이 없어요.** 사람 전체를 찾도록 배운 모델한테는 애초에 단서가 없는 입력이었던 거죠. 그래서 이 숫자를 "YOLO는 별로다"로 읽으면 안 됩니다. 실사에선 완전히 달라질 수 있어요.

### 네모 블러 vs 마스크 블러

![SAM 비교](poc/assets/figure_sam.jpg)

탐지가 주는 건 네모라서, 그대로 블러하면 배경까지 뭉개집니다. SAM에 그 네모를 던져주면 안에서 사람 영역만 골라내 주고, 그만큼 사진이 덜 망가져요.

### 삽질 두 번 — 둘 다 정답 쪽이 틀렸습니다

| | |
| --- | --- |
| ![](docs/assets/pitfall_bad_faces.jpg) | ![](docs/assets/pitfall_gt_toobig.jpg) |
| **정답이 얼굴이 아니었음.** 256px로 생성했더니 노이즈가 나왔는데, 개수는 60개로 멀쩡해서 숫자만 봐선 몰랐습니다. | **정답 상자가 얼굴보다 컸음.** 예측(파랑)이 얼굴에 딱 붙어 있는데도 MISS 처리됐어요. 모델이 아니라 채점표가 틀린 거였죠. |

두 번 다 **집계 숫자가 아니라 그려 놓은 그림이 잡아냈습니다.** 그래서 코드가 항상 시각화를 같이 저장하게 해뒀어요.

두 번째 건은 좀 아찔했던 게, 처음 결과가 YuNet 50%였습니다. 여기서 임계값을 0.5 → 0.35로 낮추면 숫자가 바로 좋아지거든요. 근데 그건 결과를 보고 채점 기준을 결과 쪽으로 끌어당기는 거라... 대신 얼굴 8장을 격자에 띄워놓고 손으로 라벨링했고, 그랬더니 96.7%가 나왔습니다.
